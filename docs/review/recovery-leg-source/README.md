# Recovery-leg source: rejected paint and editable volume guide

Status: SOURCE GEOMETRY EXPERIMENT. No generated component is admitted.

Authority: SS-specs d602775, controlled-character-source.md BP-002/BP-008 permits authored hidden surfaces and a controlled 3D source pilot, while rejecting geometry proxies as final art. Runtime parent 5a5c338. No new gameplay, presentation policy or spec pin is required for this experiment.

## Observations and change of method

The preceding contact key does not reveal the recovery boot. Built-in image_gen produced source-initial.png from that key and the retained neutral costume. The connected lower-leg component points its toe upward in image space, contrary to the existing authored recovery guide. The focused pitch correction instead produced two visible boots in source-duplicated-boot.png. Both outputs are rejected for assembly. Exact prompts are retained; no clipping or registration hides those failures.

The next safe source action was to make the concealed volume explicit using the existing pose model, rather than infer hidden anatomy from the raster. boot_geometry.py imports the existing block.py and its parameters, samples the anatomical left leg at time zero, and constructs a closed shoe loft, attached shaft and trouser segment. Heel/toe/ankle/knee positions are unchanged from that model. The shape recipe is boot-shape.json; recovery-leg.obj is editable mesh output. No Blender or other engine is required to reproduce it.

The shoe's length and maximum width use the earlier proposed block's 10 and 4 source units. Cross sections, shaft and trouser radii are explicitly authored guide values, not measurements recovered from the painted character. The components are closed separately; their intersections have not been validated as a production mesh or skinning topology.

## Visual review

This provides an explicit source relationship for the next paint attempt. It does not establish matching costume proportions, acceptable gait, a final viewing angle or correct world contact. The isolated study does not include thigh/coat occlusion or a complete character assembly.

The original contact key, active runtime art and metadata remain untouched. Next painting work must follow this geometry and maintain one connected boot, then be reviewed both isolated and assembled behind the original knee/thigh. Only after source range/depth and full-body counter-motion checks should the south cycle be expanded. Four facings, complete 16-frame locomotion, actual renderer travel and device acceptance remain open.

## Reproduction and verification

Python 3 + Pillow: `python3 boot_geometry.py`. It exports recovery-leg.obj, geometry-guide.png and geometry-record.json. Checks require finite unique vertices, nondegenerate face index sets and two incident faces per component edge. These establish basic source-mesh structure only, not anatomical/skin/art quality.
